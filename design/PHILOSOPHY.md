### Философия интерфейсов WHAT Technologies

Интерфейсы WHAT Technologies строятся на четырех базовых принципах:
1. **Чистота и глубина (OLED Dark First)**: Отсутствие визуального шума, лишних разделителей и ядовитых цветов. Глубокие фоны и многослойные поверхности `surfaceContainer`.
2. **Единая форма (Unified Rounding)**: Все интерактивные элементы, карточки и модальные окна имеют согласованный радиус скругления.
3. **Бесшовный скролл без грубых срезов**: Контейнеры с горизонтальным или вертикальным скроллом обязаны сохранять скругленные края и маскировать внутренние элементы.
4. **Тактильность и физика**: Мягкие пружинные анимации, микро-взаимодействия при клике (`BeautifulClick`), плавное появление контента.

### Стандарты геометрии и скруглений

#### 1. Единый радиус: `MaterialTheme.shapes.large`
В приложениях запрещено произвольное указание случайных `RoundedCornerShape(8.dp)`, `15.dp`, `22.dp`.
* **Все карточки (расписание, новости, профиль):** строго `shapes.large` (16–20 dp).
* **Диалоги и всплывающие окна:** `shapes.large`.
* **Маленькие чипсы и бейджи:** `shapes.small` (8–10 dp).
* **Поля ввода и поиска:** `shapes.large`.

#### 2. Критическое правило: Обязательный `.clip(...)` для списков и баннеров

> **ПРАВИЛО ПРЕДОТВРАЩЕНИЯ КВАДРАТНЫХ СРЕЗОВ:**  
> Любой скроллируемый контейнер (например, горизонтальный ряд новостей в профиле или вертикальный список занятий), а также карточки с изображениями **ОБЯЗАНЫ** иметь явный модификатор `.clip(...)`.

```kotlin
// ❌ НЕПРАВИЛЬНО (при скролле контент будет резко обрезаться прямым углом):
LazyRow(
    modifier = Modifier.fillMaxWidth().padding(horizontal = 16.dp)
) { ... }

//  ПРАВИЛЬНО (контейнер скруглен, скролл внутри остается элегантным):
Box(
    modifier = Modifier
        .fillMaxWidth()
        .padding(horizontal = 16.dp)
        .clip(MaterialTheme.shapes.large) // Обязательный клип контейнера
) {
    LazyRow(modifier = Modifier.fillMaxWidth()) { ... }
}
```

#### 3. Изображения внутри карточек
Картинки внутри карточек новостей или профилей не должны вылезать за пределы скругления карточки:
```kotlin
// Для верхней части карточки (баннер):
Image(
    modifier = Modifier
        .fillMaxWidth()
        .height(180.dp)
        .clip(RoundedCornerShape(topStart = 16.dp, topEnd = 16.dp)),
    contentScale = ContentScale.Crop,
    ...
)
```

### Организация пространства (Spacing & Grid)

1. **Горизонтальные поля экранов:**
   * Стандартный отступ от краев экрана: `16.dp`.
   * Внутренний паддинг карточки: `16.dp`.
2. **Интервалы между элементами:**
   * Вместо устаревшего `Spacer(Modifier.height(12.dp))` используется лаконичный `Gap`:
   ```kotlin
   Gap(12.dp) // из модуля foundation-ui
   ```
3. **Безопасные системные зоны (Edge-to-Edge):**
   * Все экраны используют `enableEdgeToEdge()`.
   * Паддинги `systemBarsPadding()`, `statusBarsPadding()`, `navigationBarsPadding()` применяются на верхнем уровне (в хосте навигации или на конкретных корневых экранах), а не внутри отдельных кнопок.

---

### Микро-взаимодействия и анимации

* **Клик по карточке:** Используйте модификатор `Modifier.beautifulClick { ... }` вместо стандартного грубого серого `clickable { }` — он добавляет мягкую scale-анимацию нажатия.
* **Скелетоны загрузки:** Вместо блокирующего спиннера используйте `Modifier.shimmer()` из `foundation-ui` для отрисовки скелетной анимации загрузки карточки.
